# 저학년 문제와 제한 시간 설정 점검 (2026-10-16)

## 변경

- 선생님 설정에 기본/저학년(1~3학년) 난이도 선택을 추가했습니다. 기본 설정은 기존 문제입니다.
- 저학년은 친숙한 낱말 16개, 짧은 문장 8개, 쉬운 객관식 28개를 사용합니다. 연습·타자 테스트·각 라운드·결승·AI에 같은 난이도를 적용합니다. 객관식은 중복 없는 세 보기이며, CSV 업로드 문제는 기존 네 보기를 유지합니다.
- 네 라운드 각각 경기 30~600초, 문제당 0~120초를 설정합니다. 0은 제한 없음이고 타자 릴레이는 1~120초입니다. 타자 테스트는 10~120초입니다. 결승은 선택된 종목의 설정을 상속합니다.
- 서버가 시간을 판정합니다. 시간 초과 타자는 기존 부분 점수를 한 번만 계산하고, 미응답 객관식은 감점 없이 넘깁니다. 이전 문제 ID로 늦게 도착한 입력을 거부합니다.
- 설정은 대기실의 방장만 바꿀 수 있습니다. 재접속·새 게임에도 같은 방의 설정을 유지하고 방 삭제·서버 재시작 때 사라집니다. 기존 방별 WebSocket을 사용하며 DB·API·포트·의존성을 추가하지 않았습니다.

## 검증 결과

- `npm test`: 28개 통과. 기존 경기 흐름·태블릿·AI·권한·부분 점수 회귀 검사 포함.
- `test/lesson-settings.test.js`: 문제 은행의 세 보기/정답/해설, 양 모드 난이도, 방 격리, 권한과 입력 범위, 테스트 시간, 각 라운드 시간, 개별 시간 초과와 중복 채점 방지, 객관식 미응답 무감점, 릴레이 시간, CSV 우선, 재접속/재시작 유지, 실제 2:2 결승의 시간 상속을 실제 로컬 서버와 WebSocket으로 확인했습니다.
- `npm run build`: 성공. 기존의 500KB 초과 번들 안내가 남아 있습니다.
- `node scripts/measure-load.mjs`: 학생 30명+교사 1명, 6초 동안 기존 기본 경기 시나리오에서 0.203Mbps, CPU 한 코어 기준 3.9%, 이벤트 루프 p99 15.8ms, RSS 약 67MB. 반당 1Mbps 기준 이내입니다. 실제 학교 기기·수백 명 동시 사용·짧은 문제 제한 설정의 부하 시험은 아닙니다.
- 브라우저 화면 플레이 테스트는 완료하지 못했습니다. 컴퓨터 사용 도구가 Windows의 현재 브라우저 주소를 확정하지 못해 정책상 중단됐습니다. 위 결과는 서버 흐름 검사와 빌드 결과이며 화면 조작 성공을 뜻하지 않습니다.

## 운영 반영

기능 브랜치의 검증 결과입니다. main 병합은 관리자 확인 후 진행하며, 자동 배포 시 서버 재시작으로 기존 방이 초기화됩니다. 운영 반영 여부는 PR 병합·배포 결과를 별도로 확인해야 합니다.
