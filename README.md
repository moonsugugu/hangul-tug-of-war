# 말모이 줄다리기

한글날을 기념하는 실시간 타자 줄다리기 게임입니다. 학생들은 한 서버에 접속해 청팀과 백팀으로 나뉘고, 순우리말·바른 문장·한글 관련 문장을 입력하며 세종대왕님 심판 아래 줄다리기를 진행합니다.

## 주요 모드

- 말모이 기본전: 순우리말을 입력하고 제출 후 뜻과 예문을 확인합니다.
- 뜻풀이 객관식 역전전: 뜻을 읽고 알맞은 순우리말을 선택하며, 한글 창제·훈민정음 관련 배움 문제도 만납니다.
- 바른말 수리공: 띄어쓰기 문제 119개(`server/spacing-prompts.js`)가 플레이어마다 무작위 순서로 나오고, 라운드마다 새로 섞입니다.
- 훈민정음 랜덤 릴레이: 각 팀에서 서버가 랜덤으로 대표를 뽑아 같은 문장으로 대결합니다.

## 화면 연출

- 입장할 때 토끼·곰·고양이·병아리·판다·양·여우·펭귄 중 캐릭터를 고릅니다.
- 제공된 궁궐 경기장·캐릭터·NPC·응원 소품 스프라이트를 `public/assets`에 보관하고 Three.js 2.5D 레이어로 조합합니다.
- 세종대왕님 심판, 조선시대 응원 NPC, 팀 캐릭터, 실제 줄다리기 줄과 팀 깃발이 함께 움직입니다.
- 문제 결과에서는 순우리말의 뜻·예문과 한글 창제 문제의 해설을 함께 제공합니다.

## 서버 규칙

- 점수 계산과 라운드 시간은 서버가 담당합니다.
- 2라운드 객관식은 네 가지 보기로 출제됩니다. 순우리말 뜻 문제와 한글 창제 원리·세종대왕 관련 역사 문제가 번갈아 나오며, 오답을 고르면 해당 팀 점수에서 30점이 감점됩니다. 라운드 시작 안내에도 감점 규칙을 표시합니다.
- 객관식 문제는 학생마다 따로 섞은 묶음에서 꺼내고 한 번 낸 문제는 빼 두므로, 순우리말 문제와 한글 창제 문제를 모두 풀기 전에는 같은 문제가 다시 나오지 않습니다. 라운드나 새 게임이 바뀌어도 이어서 쓰며, 한글 창제 문제를 다 풀면 순우리말 문제만 이어서 나옵니다. 보기를 두 번 눌러도 늦게 도착한 답은 다음 문제에 적용하지 않습니다.
- 한 방에는 최대 30명까지 입장할 수 있습니다. 참가자가 많아질수록 경기장 줄이 길어지고 캐릭터는 작아집니다.
- 각 라운드 시작 전에 5초 동안 종목 설명을 보여 줍니다. 네 종목을 각각 3분 동안 진행하며, 점수와 줄 위치, 끝까지 당긴 횟수는 라운드마다 초기화합니다.
- 1~4라운드(결승 포함) 모두 줄을 한쪽 끝(20칸, 점수 차 1,500점)까지 당기면 그 팀의 '끝까지 당긴 횟수'가 1 오르고 줄은 가운데로 돌아갑니다. 5번을 먼저 채운 팀이 그 라운드에서 1승을 얻습니다.
- 제한시간이 끝나면 끝까지 당긴 횟수가 많은 팀이, 횟수가 같으면 그때 줄이 기운 팀이 이깁니다. 그래도 동점이면 10초씩 연장합니다. 네 라운드 뒤 승수가 2:2이면 돌림판이 네 종목 중 하나를 골라 5라운드 결승을 진행합니다.
- 릴레이에서도 다른 라운드처럼 모든 참가자의 타자 점수(정확도·속도)가 팀 점수가 되어 줄을 당깁니다(점수 차 75점마다 1칸, 라운드 배율·인원 보정 적용). 대표로 뽑힌 학생의 점수는 2배로 들어갑니다. 한 대결에서 각자 한 번씩 제출할 수 있고, 대결마다 대표가 바뀝니다. 릴레이 동점이 2회 연장 후에도 계속되면 추첨으로 라운드 승자를 정합니다.
- 객관식 선택지는 문제마다 무작위 순서로 보여 주며, 연속 문제에서 정답 위치가 같지 않도록 합니다.
- 타자 입력 라운드에서는 제한시간에 제출하지 못했더라도 종료 순간까지 입력한 내용의 정확도·속도를 계산해 부분 점수를 줍니다. 릴레이의 12초 대결 시간에도 같은 규칙을 적용하며(대표는 2배), 이미 제출한 답안은 다시 채점하지 않습니다.
- 팀별 인원이 다르면 적은 인원의 팀에 `많은 팀 인원 ÷ 적은 팀 인원` 보정 배율을 적용합니다.
- 따라서 4명 대 5명이라면 4명 팀의 점수는 1.25배가 됩니다.
- 랜덤 릴레이 대표는 한 사이클 안에서 모든 참가자가 한 번씩 선택될 때까지 중복 선택되지 않습니다.

## 실행

```bash
npm install
npm run dev
```

- 화면: http://localhost:5173
- 서버/헬스 체크: http://localhost:8787/health
- 첫 번째로 입장한 참가자가 진행자 권한을 갖습니다.
- 배포용 정적 파일은 `npm run build`로 생성됩니다.

- **집 노트북 1대**(Lenovo IdeaPad L340 · i5-9300H 4코어 8스레드 · RAM 8GB · Windows 11)가 moonsunezip.com 의 앱 전부를 서비스합니다.

### 배포 흐름 — 반드시 이해하고 수정하세요

1. 배포 브랜치에 push 하면 서버가 **3분 안에** 감지합니다.
2. 서버는 `git reset --hard origin/<브랜치>` 로 코드를 **통째로 덮어쓰고** → `npm ci` → `npm run build` → PM2 재시작 순서로 배포합니다.
3. 빌드나 헬스체크가 실패하면 **이전 버전으로 자동 롤백**되고 사이트는 이전 상태로 유지됩니다.

따라서:
- **서버 폴더를 직접 고치지 마세요.** 다음 배포 때 사라지거나, "커밋 안 된 수정"으로 판단돼 배포가 멈춥니다.
- `package-lock.json` 을 반드시 커밋하세요(`npm ci` 는 lock 파일이 없으면 실패합니다).
- **게임 서버가 있는 앱은 배포 = 서버 재시작 = 진행 중인 방이 전부 사라짐** 입니다. 수업 시간에는 push 하지 마세요.

### 실시간·게임 코드를 짤 때 지킬 것 (실제로 겪은 문제들)

| 규칙 | 이유 |
|---|---|
| 서버는 `HOST`, `PORT` 환경변수를 읽고 기본값을 `127.0.0.1` 로 | 주소를 `0.0.0.0` 으로 코드에 고정하면 서버 설정으로 바꿀 수 없음 |
| **IP 당 제한을 걸지 마세요** | 학교는 전교생이 **공인 IP 하나**로 나갑니다. 윷놀이의 "IP당 방 6개" 제한이 학교 전체를 막았습니다 |
| 방 상태 전송 시각·타이머는 **방마다 따로** | 전역 변수 하나로 두면 한 반의 활동이 다른 반 갱신을 밀어냅니다(줄다리기에서 최장 4초 멈춤) |
| 큰 상태를 자주 보내면 WebSocket 압축(`perMessageDeflate`) | 줄다리기 20개 반 기준 161Mbps → 3Mbps |
| 끊긴 학생이 **60초 안에 같은 자리로 재접속**할 수 있게 | 교실 와이파이는 자주 끊깁니다. 빈 방도 60초는 유지하세요 |
| 요청 처리 중 동기 파일 I/O·느린 OS 호출 금지 | Windows 에서 `os.networkInterfaces()` 1회 25ms → 30명 방에서 서버가 멈췄습니다 |
| 요청마다 목록 전체를 훑는 코드 금지 | 사용자가 늘수록 느려집니다(backend 처리량이 4분의 1이던 원인) |
| 비밀값(키·비밀번호)은 저장소에 넣지 않기 | 서버의 비밀값은 `C:\homeserver\secrets` 에 따로 있습니다 |

**부하 목표: 한 학교 20개 반 동시 사용(약 600명).** 전국 배포라 한글날처럼 특정 날에 몰립니다.
