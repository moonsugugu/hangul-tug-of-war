# 말모이 줄다리기

한글날을 기념하는 실시간 타자 줄다리기 게임입니다. 학생들은 한 서버에 접속해 청팀과 백팀으로 나뉘고, 순우리말·바른 문장·한글 관련 문장을 입력하며 세종대왕님 심판 아래 줄다리기를 진행합니다.

## 주요 모드

방을 처음 만들 때 **기존 타자 모드** 또는 **태블릿 객관식 모드**를 선택합니다. 초대받은 참가자는 같은 방 모드를 사용하며, 새 게임을 준비해도 모드는 유지됩니다.

### 태블릿 객관식 모드

- 키보드 없이 태블릿 터치만으로 경기합니다. 진행자가 PC에서 방을 만들거나 참가하는 것도 가능합니다.
- 타자 연습과 30초 타자 테스트를 건너뛰고, 인원수가 최대한 같도록 팀을 무작위로 나눕니다.
- 순우리말 뜻풀이 → 한글 창제 원리 → 세종대왕 이야기 → 말모이 종합 퀴즈를 각각 3분 동안 진행합니다. 2:2일 때 돌림판으로 고르는 결승도 객관식입니다.
- 모든 문제는 서로 다른 보기 4개입니다. 정답 위치는 무작위이며, 같은 문제의 보기는 상태 갱신 중 바뀌지 않습니다.
- 정답 기본 60점에 속도 보너스 최대 40점을 더합니다. 보너스는 `40 × (1 − min(걸린 시간, 8초) ÷ 8초)`이며, 8초 이후 정답도 기본 60점을 얻습니다. 정답에는 기존 라운드 배율과 인원 보정이 적용됩니다.
- 오답은 해당 팀 점수에서 정확히 30점 감점합니다. 팀 점수가 0점이어도 음수로 내려갑니다. 한 번 고르면 다음 문제로 넘어가고, 같은 문제의 연속 터치는 한 번만 채점합니다.

### 기존 타자 모드

- 말모이 기본전: 순우리말을 입력하고 제출 후 뜻과 예문을 확인합니다.
- 뜻풀이 객관식 역전전: 뜻을 읽고 알맞은 순우리말을 선택하며, 한글 창제·훈민정음 관련 배움 문제도 만납니다.
- 바른말 수리공: 띄어쓰기 문제 119개(`server/spacing-prompts.js`)가 플레이어마다 무작위 순서로 나오고, 라운드마다 새로 섞입니다.
- 훈민정음 랜덤 릴레이: 각 팀에서 서버가 랜덤으로 대표를 뽑아 같은 문장으로 대결합니다.

### 선생님 혼자 시작하기

- 방을 만든 선생님에게 **대기 모드 시작**, **AI와 붙기** 버튼이 표시됩니다. 두 모드에서는 선생님이 청팀으로 직접 문제를 풀며, 학급 경기 참가 설정은 보관합니다.
- **대기 모드**에서는 QR 코드와 방 코드를 계속 표시하고 1~4라운드를 혼자 연습합니다. 원하는 라운드로 바로 이동할 수 있고, 네 번째 라운드 뒤에는 첫 라운드로 돌아갑니다. 학생들은 연습 도중에도 입장하여 기다릴 수 있습니다.
- 실제 경기 참가자가 2명 이상 모이면 **학급 경기 시작**으로 본 경기를 시작합니다. 연습 점수는 초기화하고 선생님의 참가 설정에 따라 팀을 새로 나눕니다. **설정으로 돌아가기**로 CSV와 참가 설정을 바꿀 수도 있습니다.
- **AI와 붙기**는 방에 선생님 혼자 있을 때 시작하는 1:1 경기입니다. 1~10단계 중 선택하며 높은 단계일수록 답을 더 빠르고 정확하게 제출합니다. 타자 모드와 태블릿 객관식 모드를 모두 지원합니다.
- AI는 서버에서 실행하는 컴퓨터 상대이며 외부 AI API를 호출하지 않습니다. 실제 답안을 제출하여 사람과 같은 채점·오답 감점·전체 점수 배율을 적용받습니다. 결과 화면에서 같은 단계나 다음 단계로 다시 도전할 수 있습니다.
- **학급 대기실로 돌아가기**를 누르면 AI를 제거하고 기존 선생님 참가 설정을 복원합니다. 사람 참가자가 모두 나가면 방과 AI를 함께 정리합니다.

## 선생님 CSV 문제 설정

방을 만든 선생님(방장)은 게임 시작 전 대기실의 **선생님 설정**에서 **예시 양식 다운로드** → 문제 작성 → **CSV 문제 업로드** 순서로 객관식 문제를 넣을 수 있습니다. Excel에서는 `CSV UTF-8`로 저장하세요. 한글 Windows CSV도 읽을 수 있습니다.

- 필수 열: `문제,보기1,보기2,보기3,보기4,정답`
- 선택 열: `해설,분류` (열을 생략하거나 내용을 비워도 됩니다.)
- `정답`은 보기의 번호 `1~4` 또는 정답 보기의 문구입니다. 보기 네 개는 비어 있지 않고 서로 달라야 합니다.
- 한 파일에 최대 200문제, 파일 크기는 256KB 이내입니다. 쉼표·큰따옴표·줄바꿈이 포함된 셀은 일반 CSV 인용 규칙을 사용합니다. 다운로드 양식에 쉼표 예시도 들어 있습니다.
- 잘못된 파일은 행 번호와 오류 내용을 표시하며, 기존에 적용한 문제를 덮어쓰지 않습니다. 서버도 문제를 다시 검사합니다.
- 태블릿 모드에서는 모든 라운드·결승에, 기존 타자 모드에서는 객관식 라운드에 업로드한 문제만 무작위로 출제합니다. 정답·해설은 선택을 제출한 뒤 알려 줍니다.
- 적용된 파일명·문제 수를 설정에서 확인하고, **기본 문제로 되돌리기**로 복원할 수 있습니다. 학생은 문제를 바꿀 수 없으며 경기 중 업로드·복원도 차단됩니다.
- 업로드한 문제는 휘발 데이터로 그 방의 메모리에만 보관합니다. 새 게임 준비에는 유지되고, 방 삭제·서버 재시작 시 사라지므로 선생님은 원본 CSV를 보관해야 합니다. 별도의 DB·외부 API는 추가하지 않습니다.

예시 양식 파일: `public/templates/malmoe-quiz-example.csv` (Excel 한글 호환을 위한 UTF-8 BOM 포함).

## 경기 중 점수 배율과 오답 복습

- 경기 화면의 **전체 참가자 점수 배율**에서 선생님(방장)이 `1배~7배`의 7단계를 선택합니다. 청팀·백팀 모든 경기 참가자에게 공통 적용하며, 기본은 1배이고 학생 화면에도 전체 배율이 표시됩니다. 배율을 높이면 한 답안이 줄을 더 크게 움직여 승부가 빨리 납니다.
- 양 팀의 이후 득점·객관식 감점·릴레이·시간 종료 부분 점수에 적용하며, 기존 점수는 바꾸지 않습니다. 기존 라운드·인원 보정은 그대로 적용합니다. 예를 들어 3배에서는 기본 객관식 오답 감점이 90점입니다.
- 라운드 사이와 결승 준비 중에도 변경할 수 있고 다음 라운드·새 게임 준비에 유지됩니다. 배율은 기존 방 메모리에 보관하는 휘발 데이터입니다.
- 오답은 제출한 답, 정답, 문제 해설을 **3초 동안 팝업**으로 보여 준 뒤 자동으로 닫습니다. CSV에 해설이 없으면 정답 안내를 표시합니다.
- 객관식·일반 타자의 다음 문제는 팝업이 닫힌 뒤부터 속도 보너스를 계산하고, 복습 중 중복 제출은 서버에서도 차단합니다.

## 선생님 경기 참가 설정

- 새 화면으로 만든 방에서는 선생님이 기본으로 **참가하지 않고 진행만 하기**를 사용합니다. 대기실 **선생님 설정 → 선생님 경기 참가**에서 진행만 하기, 팀 자동 배정으로 참가하기, 청팀 참가, 백팀 참가 중 선택합니다.
- 진행만 하는 선생님은 팀 인원·인원 보정·타자 테스트·릴레이 대표·득점에서 제외하고, 경기 화면에는 답안 입력 대신 진행자 안내를 보여 줍니다. CSV 설정, 경기 시작, 전체 참가자 점수 배율 조정, 새 게임 준비 권한은 유지합니다.
- 선생님이 참가하면 한 팀의 선수로 채점합니다. 팀을 직접 선택해도 나머지 참가자는 인원과 실력을 고려해 나눕니다. 참가 방식은 경기 시작 전에만 바꾸며 새 게임 준비에도 유지합니다.
- 참가 방식은 기존 방의 휘발 메모리에 보관하며 기존 `/ws`로 방에만 전송합니다. 이전 클라이언트에서 만든 방은 자동 배정 참가를 유지하고 설정에서 변경할 수 있습니다.

## 라운드 사이 설명 대기

- 라운드가 끝나면 결과와 다음 라운드 설명을 **15초** 동안 보여 줍니다. 시간이 끝나면 다음 라운드를 바로 시작하고 설명 대기를 중복하지 않습니다.
- 첫 라운드와 돌림판으로 정해진 결승의 시작 설명도 15초입니다. 선생님만 **다음 라운드 바로 시작** 버튼으로 설명 대기를 건너뛸 수 있습니다. 학생은 버튼이 없고 서버에서도 전환 요청을 거부합니다.
- 늦게 도착한 클릭이나 연속 터치가 다른 라운드를 넘기지 않도록 현재 단계·라운드를 서버에서 확인합니다.

## 화면 연출

- 첫 화면에는 실제 AI 경기의 줄다리기 장면을 담은 짧은 영상이 음소거로 반복 재생됩니다. 재생·일시정지 버튼을 제공하며 동작 줄이기를 설정한 기기에서는 자동 재생을 멈춥니다. 영상과 포스터는 `public/videos`에 보관합니다.
- 입장할 때 토끼·곰·고양이·병아리·판다·양·여우·펭귄 중 캐릭터를 고릅니다.
- 제공된 궁궐 경기장·캐릭터·NPC·응원 소품 스프라이트를 `public/assets`에 보관하고 Three.js 2.5D 레이어로 조합합니다.
- 세종대왕님 심판, 조선시대 응원 NPC, 팀 캐릭터, 실제 줄다리기 줄과 팀 깃발이 함께 움직입니다.
- 문제 결과에서는 순우리말의 뜻·예문과 한글 창제 문제의 해설을 함께 제공합니다.

## 서버 규칙

- 점수 계산과 라운드 시간은 서버가 담당합니다.
- 2라운드 객관식은 네 가지 보기로 출제됩니다. 순우리말 뜻 문제와 한글 창제 원리·세종대왕 관련 역사 문제가 번갈아 나오며, 오답을 고르면 해당 팀 점수에서 30점이 감점됩니다. 라운드 시작 안내에도 감점 규칙을 표시합니다.
- 한 방에는 최대 30명까지 입장할 수 있습니다. 참가자가 많아질수록 경기장 줄이 길어지고 캐릭터는 작아집니다.
- 첫 라운드·결승 시작 안내와 라운드 사이 설명 대기는 각각 15초이며 선생님은 바로 시작할 수 있습니다. 네 종목을 각각 3분 동안 진행하며, 점수와 줄 위치는 라운드마다 초기화합니다. 일반 종목은 줄을 20칸 먼저 당기거나 제한시간에 앞선 팀이 그 라운드에서 1승을 얻습니다.
- 제한시간에 동점이면 10초씩 연장합니다. 네 라운드 뒤 승수가 2:2이면 돌림판이 네 종목 중 하나를 골라 5라운드 결승을 진행합니다.
- 릴레이에서는 대표가 정확히 입력하면 줄을 2칸 당기고, 같은 문장을 입력한 팀원은 한 명당 1점을 보탭니다. 한 대결에서 각자 한 번씩 제출할 수 있습니다. 줄이 끝까지 가더라도 릴레이는 조기 종료하지 않고 제한시간까지 대표가 번갈아 대결합니다. 릴레이 동점이 2회 연장 후에도 계속되면 추첨으로 라운드 승자를 정합니다.
- 객관식 선택지는 문제마다 무작위 순서로 보여 주며, 연속 문제에서 정답 위치가 같지 않도록 합니다.
- 타자 입력 라운드에서는 제한시간에 제출하지 못했더라도 종료 순간까지 입력한 내용의 정확도·속도를 계산해 부분 점수를 줍니다. 릴레이의 12초 대결 시간에도 같은 규칙을 적용하며, 이미 제출한 답안은 다시 채점하지 않습니다.
- 팀별 인원이 다르면 적은 인원의 팀에 `많은 팀 인원 ÷ 적은 팀 인원` 보정 배율을 적용합니다.
- 따라서 4명 대 5명이라면 4명 팀의 점수는 1.25배가 됩니다.
- 랜덤 릴레이 대표는 한 사이클 안에서 모든 참가자가 한 번씩 선택될 때까지 중복 선택되지 않습니다.

## 실행

```bash
npm install
npm run dev
```

- 화면: http://localhost:5173
- 서버/헬스 체크: http://localhost:8787/health
- 첫 번째로 입장한 참가자가 진행자 권한을 갖습니다.
- 배포용 정적 파일은 `npm run build`로 생성됩니다.
- 자동 검증: `npm test` (기존 경기 흐름 및 태블릿 객관식 전체 경기·점수 검증).
- 화면 개발 서버와 게임 서버 모두 `127.0.0.1`에만 바인딩합니다.

방 설정·문제 진행·경기 점수는 휘발 데이터로 기존 게임 서버의 방별 메모리에 보관합니다. 기존 `tug.moonsunezip.com/ws` 연결과 방별 전송을 사용하며 DB·새 API·새 포트는 추가하지 않습니다. 서버 재시작 시 방은 사라집니다.

- **집 노트북 1대**(Lenovo IdeaPad L340 · i5-9300H 4코어 8스레드 · RAM 8GB · Windows 11)가 moonsunezip.com 의 앱 전부를 서비스합니다.

### 배포 흐름 — 반드시 이해하고 수정하세요

1. 배포 브랜치에 push 하면 서버가 **3분 안에** 감지합니다.
2. 서버는 `git reset --hard origin/<브랜치>` 로 코드를 **통째로 덮어쓰고** → `npm ci` → `npm run build` → PM2 재시작 순서로 배포합니다.
3. 빌드나 헬스체크가 실패하면 **이전 버전으로 자동 롤백**되고 사이트는 이전 상태로 유지됩니다.

따라서:
- **서버 폴더를 직접 고치지 마세요.** 다음 배포 때 사라지거나, "커밋 안 된 수정"으로 판단돼 배포가 멈춥니다.
- `package-lock.json` 을 반드시 커밋하세요(`npm ci` 는 lock 파일이 없으면 실패합니다).
- **게임 서버가 있는 앱은 배포 = 서버 재시작 = 진행 중인 방이 전부 사라짐** 입니다. push 하기 전에 서버 관리자에게 물어보세요(`.md` 문서만 바꾼 push는 재시작 없음).

## 서버 전송 (2026-10-02)

- 새 화면(`rows=1`)은 명단 인원이 그대로면 `players` 전체 대신 바뀐 학생 줄만 `pu: [[번호, 항목], …]`로, 순서만 바뀌면 `po`(새 자리마다 이전 번호)로 받습니다. 화면의 `mergeState`가 합칩니다. 점수 하나 바뀔 때마다 `players` 전체를 다시 보내던 것이 메시지의 대부분이었습니다.
- WebSocket 압축은 기본으로 끕니다(`WS_COMPRESS=1`이면 켬). 메시지가 작아져 압축 이득보다 비용이 큽니다.
- 서버 노트북 실측(30명 반, 학생이 0.5초마다 답): 반당 CPU 3.6% → 2.3%, 반당 전송량 약 0.32Mbps(규칙 1Mbps 이내).
- 시험: `node scripts/rows-check.mjs . tug 5201` — 새 화면이 합친 명단이 예전 방식과 같은지(중간 입장·끊김 포함), 경기 중에는 명단 전체를 보내지 않는지.

## 서버 나누기 (3개, 2026-10-02)

서버 하나는 약 30~35개 반이 한계(메인 스레드)라서 같은 서버를 3개 띄워 방을 나눠 맡깁니다.

- `SHARD_COUNT` · `SHARD_ID` 가 없으면 지금처럼 서버 하나로 돕니다.
- 방 코드 첫 글자 = 서버 번호(서버 1·2·3 → `2`·`3`·`4`). 화면은 코드를 보고 `/ws/sN` 으로 접속합니다(QR 입장·새로고침 복귀 포함). 방을 만들 때는 `/ws/s1~s3/health` 를 보고 가장 한가한 서버로 다시 연결해 만듭니다.
- 서버 3개: `hangul-tug`(3008, SHARD_ID=1) · `hangul-tug-2`(3408, 2) · `hangul-tug-3`(3418, 3), 셋 다 `SHARD_COUNT=3`, 같은 폴더. Cloudflare 경로 `^/ws/s2(/|$)` → 3408, `s3` → 3418, 나머지는 3008.
- 시험: `node scripts/shard-smoke.mjs` — 서버 3개와 Cloudflare 처럼 경로를 나누는 중계기를 띄워 11개 항목 확인. `KEEP=1` 이면 http://127.0.0.1:4600 에서 화면으로 확인할 수 있습니다.

## 📏 코드 규칙 (coderule)

> 이 저장소를 고치기 전에 **[moonsugugu/coderule](https://github.com/moonsugugu/coderule)** 을 먼저 읽으세요. 사람과 AI 모두 지킵니다.

**핵심 여섯 가지**

1. **30명 반 하나의 전송량은 1Mbps 이하.** `메시지 크기(바이트) × 초당 횟수 × 받는 사람 수 × 8 ÷ 1,000,000` 으로 완료 전에 잰다.
   2026-10-02 고조선이 30명 방 하나에 22Mbps를 써서, 20개 반이 몰리자 집 업로드(약 170Mbps)가 막혀 모든 앱이 끊겼다.
2. **바뀐 것만 보내고, WebSocket 압축(`perMessageDeflate`)을 켜고,** 위치처럼 계속 바뀌는 값은 초당 5~7회 + 화면 보간. 입력마다 즉시 방송하지 말고 50~150ms 모아서 보낸다.
3. **인원 제한에 선생님을 세지 않는다. IP당 제한을 걸지 않는다**(학교는 전교생이 공인 IP 하나).
4. **방마다 타이머 따로, 끊긴 학생은 60초 이상 같은 자리 유지,** 서버는 `HOST`·`PORT` 환경변수(기본 `127.0.0.1`), 요청 경로에 동기 I/O 금지.
5. **배포·앱 재시작·터널 재시작은 서버 관리자에게 물어보고 한다.** 배포 = 서버 재시작 = 진행 중인 방이 전부 사라진다. (README 같은 `.md` 문서만 바꾼 push는 재시작 없이 반영된다)
6. **서버가 바쁘면 끊지 말고 느리게(과부하 보호, 규칙 19).** 이벤트 루프 지연으로 바쁨을 재서 바쁘면 방송 간격을 2~3배로 늘리고, 바쁜 동안은 하트비트로 연결을 끊지 않고, 매우 바쁠 때만 **새 방 만들기**를 "지금 사용자가 많아 순서대로 처리 중입니다" 안내로 막는다(수업 중인 반은 그대로). `/health` 의 `load` 로 확인. 구현은 `server/load-guard.mjs` — coderule `tools/load-guard.mjs` 를 그대로 복사해 쓰고, 끄려면 `LOAD_GUARD=0`.

**이 저장소 점검(2026-10-02):** 이미 규칙을 지키고 있습니다(압축 켜짐, 방마다 따로 0.5초 갱신, networkInterfaces 캐시).
